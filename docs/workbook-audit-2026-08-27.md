# workbook-audit-2026-08-27

## scope-and-method

Full values-level review of all 24 tabs of the shared workbook on 2026-08-27, via a Drive text export of the live spreadsheet, plus a line-by-line review of `apps-script/code.gs`. The export shows displayed values only, so formula text, cell formats, and embedded charts were reviewed indirectly through the Apps Script contract and repaired through new menu functions. Zero Sheets error literals (`#REF!`, `#N/A`, `#VALUE!`, `#DIV/0!`, `#NAME?`, `#NUM!`, `#ERROR!`, `#NULL!`) were present in displayed values at audit time. Analytics cross-foots cleanly: round counts, position counts, and team counts each sum to 257.

## observations-not-changed

- `Big Board` Size column is empty for every exported row, so the Size metric in `Players-Compare` always renders blank. Populating it needs a data decision (a height and weight composite or an NFL source field), so it is recorded here rather than guessed.
- `Analytics` `Average Value Vs Rank` and `Average Actual Vs Projected` both read -22.1 because `Big Board` projected overall equals board rank, making the two metrics mathematically identical. Redundant, not wrong.
- `Team-Needs` is empty by design (commissioner input), which is why the tracker `Need Fit` and `Status` columns are blank.
- `Draft History` holds headers only and states that historical seasons are not loaded.
- `_config` participant colors are the same two hex values for all 12 fantasy teams, placeholders rather than per-team branding.
- `Draft Rules` marks `Rules Published: No` as `PASS/READY`, while Dashboard counts it as a readiness gap. The basic check validates presence, not publication, which is defensible but worth knowing.

## addendum-independent-review-findings

An adversarial code review of the repair layer confirmed and reproduced five defects in the first implementation, all fixed and now regression-tested: the Board-By Position rebuild could wipe 424 rows of column data when only a header was renamed (now a tri-state check that skips unrecognized layouts and verifies the full 12-column header before clearing); `repairKnownIssues` aborted mid-run with partial writes and no log when any sheet was missing (now every repair is fault-isolated and the log always lands); the Commissioner Dashboard stray-cell scan eroded one extra cell per rerun via stale-snapshot neighbor checks (now a single-snapshot row-orphan rule that also spares merged rows); the Start Here repair reported `REPAIRED` on every run including no-ops (now health-gated); and the post-draft auto-stop left `_updates!B2` reading `LIVE` with no poller while the trigger check failed forever (completion now writes `COMPLETE` and the check passes as `automation ready` when the draft is done). Grid-bounds guards (`ensureRows_`) now precede every fixed-extent write so trimmed sheets grow instead of throwing.

## addendum-2026-08-27-projection-restructure

The owner restructured `Players-Draft Tracker` into a projection board (Player, Proj Team, Pos, NFL Grade, Proj Pick, Act Pick, Act Team, Board Rank, Value vs Rank, Proj Round, Act Round, College, Production, Athleticism, Need Fit, Status), with Proj Pick and Act Pick as within-round pick numbers. That change is authoritative; this repo was updated to match it. Consequences found and resolved: the refresh contract would have overwritten the new columns A:E with the five-column feed, so the feed now writes a script-managed `_actuals` staging tab and never touches the tracker; Value vs Rank computed against an empty Act Pick, producing minus-board-rank values across all 257 rows and corrupting Analytics averages, so the Act columns and Value vs Rank are now guarded formulas that stay blank until actuals exist; Analytics round, team, and position blocks showed `#VALUE!` from the moved columns and are rewritten against `_actuals`; the Team-Compare and Team-Report pick tables lost their Overall column and carried the corrupted values, so all four team-view blocks are rebuilt as one `_actuals`-plus-Big-Board `FILTER` each; Mock Lab's order column broke to `#N/A` and now derives from the tracker projection columns; and the `_updates` pick counters, Start Here status, saved-analysis performance columns, and mobile view now count `_actuals` rather than tracker columns that hold projections. One item remains open at the time of writing: a parallel session is mid-flight on `buildSeasonForecast_`, whose `forecastLayout_` helper is not yet in `code.gs`, so the three season-forecast tests are red until that lands.

## addendum-2026-08-28-adversarial-review

A six-dimension adversarial review ran across the workbook export and the Apps Script, with every claimed defect handed to an independent skeptic instructed to refute it. 61 findings survived refutation and 19 were refuted. The dimensions were tracker column-contract drift, runtime formula semantics, destructive and non-idempotent writes, the live-refresh lifecycle, live spreadsheet data integrity, and test-suite fidelity.

The root cause behind most of the code findings is the same: hardcoded geometry (column letters, row windows, block anchors) checked against a workbook the owner keeps restructuring. The fix is structural rather than cosmetic. `resolveTrackerColumns_` now reads the tracker header at runtime and maps every field by label, returning null when a label is missing or duplicated; every tracker consumer resolves first and skips with a named reason rather than writing formulas over whatever occupies the position it assumed. `TRACKER_COLUMNS` remains as the documented default and label source, and a test asserts it agrees with the live header so it can never silently drift again.
