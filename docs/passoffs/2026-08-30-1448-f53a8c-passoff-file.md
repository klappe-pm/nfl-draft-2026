## Key decisions

- Use public RSS feeds and publisher pages for episode discovery because no confirmed first-party public content API was found for either selected publisher.
- Keep full audio and transcripts in a user-controlled local machine or VPS, while the workbook stores only metadata, permitted excerpts, structured findings, and source links.
- Require direct ESPN league snapshots for lineup, waiver, matchup, and opponent-specific recommendations, while excluding generic ESPN editorial content.
- Keep every source opinion separate from provider facts and require timestamped evidence for every displayed recommendation.

## Risks and open questions

- Runtime source ingestion, transcript-worker deployment, ESPN league ingestion, and recommendation generation are planned but not implemented in this documentation slice.
- The user must provide ESPN sport, season, league ID, and public or private status before direct league ingestion can be validated. Private access requires user-managed credentials stored outside chat.
- Podcast feeds and publisher terms can change, so the worker must validate each source response and retain only material permitted by the source policy.
- The user must select the local or VPS host and transcript engine before a worker can be deployed.
